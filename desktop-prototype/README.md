# Solanime desktop preview

This is a separate Windows and macOS test app for the popup-containment experiment. It loads the deployed Solanime site inside an app-owned Electron/Chromium window. It is **not** a native media resolver, a Brave fork, or a substitute for the Android/iPhone prototypes.

The host rejects all new windows, cancels document navigation outside the exact Solanime or known provider embed hosts, declines downloads and non-fullscreen permissions, and blocks the single ad hostname observed in the prior Android test. It does not claim complete ad filtering; an ad inside the allowed provider page or a newly observed request host may still appear. The provider can also refuse playback under these controls.

Electron's remote-content security settings remain enabled: no Node integration, no preload/native bridge, context isolation, process sandboxing, and web security. No provider code is given filesystem access. The desktop app stores its own session separately from the user's normal browser.

From this directory, run `pnpm install`, `pnpm test`, `pnpm smoke`, `pnpm smoke:playback`, then `pnpm package:win` on Windows or `pnpm package:mac` on a Mac. The package scripts create new uniquely named directories under the repository's ignored `build/desktop-preview/` folder; they never overwrite an older build. Set `SOLANIME_ARTIFACTS_DIR` to use a different output folder. Set `SOLANIME_PREVIEW_EXE` to the packaged executable path to run the smoke tests against the packaged app; `pnpm smoke:interactions` specifically requires it. Set `SOLANIME_WATCH_URL` to run `smoke:playback` on another exact Solanime watch route and provider mapping. That smoke now checks the selected source and final `server` query as well as five seconds of advancing video and decoded frames, so automatic provider fallback cannot create a false pass. An unsigned Mac bundle made on Windows is not claimed: Electron Packager requires symlink privileges for that cross-build and macOS signing/notarization requires a Mac. No production website deployment is part of this preview.

On 2026-09-28, the packaged Windows x64 build passed a click-triggered synthetic popup test with zero created windows and a stable Solanime route. On 2026-09-29, the updated host rejected a user-clicked `window.open` attempt inside the live MegaPlay frame and the known mapping `384944` (Unlimited Psychic Squad, episode `124554`, subtitled) advanced from 16.42 to 21.99 seconds and 47 to 181 decoded frames, with zero created windows and a stable watch route. A separate off-site link click stayed on Solanime. The updated Windows package then passed the same mapping with 22.71 to 28.29 seconds and 32 to 166 frames.

On an Apple Silicon Mac, packaged version `0.1.0` passed exact mapping checks for `384944` and `384943` (Unlimited Psychic Squad), `52635` (100 Meters), and `1996` (One Piece). Each showed at least five seconds of advancing media time and decoded frames, a denied clicked popup attempt, zero new windows, and the selected mapping and Solanime route stable. The `384944` interaction smoke also passed Play/Pause/Resume, keyboard seek, fullscreen enter/exit, source switch to `384943`, next-episode playback and return, and restart playback with zero new windows. Earlier runs saw a provider-frame detach, a source-switch timing miss, and a restart video timeout; these remain intermittent observations. These measurements predate the account-approval gate. The later packaged Mac run reached sign-in with zero new windows but could not reach provider playback without an approved session. See the dated handoff for exact commands, measurements, screenshots, and limits; current authenticated Mac playback acceptance remains open.
