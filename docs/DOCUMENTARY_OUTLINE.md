# Documentary demonstration outline

## 1. Establish the scope

Show the exact reference domain, its HTTP→HTTPS redirect, the generic watch
404, and a real title route. Compare filter pagination with sitemap discovery.
Explain the dated 8,949-route union, rather than claiming possession of the
operator's private database. Distinguish direct observations, source claims,
unresolved research leads and the older superseded delivery attachment.

## 2. Follow a real record

Use *The Dull Sword*. Show its original title/episode IDs and the independently
reviewed Wikidata/Commons/Archive crosswalk. Explain why the four-minute restored
silent edition has a separate version instead of overwriting the two-minute SUB
description. Show that HD-1, HD-2 and Vidstream-2 remain separate identities even
when their observed backend hostname is shared.

Source: [the exact identity and rights evidence](native-provider-evidence.md).

## 3. Show the working product

Browse, search, open title details, choose the restored-silent episode and select
its actual native provider. Observe the native video's time progression, seek
with the real controls, refresh and resume. Return Home through Continue Watching.
Demonstrate episode notes as private profile data, not a fabricated public
comment thread. Show keyboard, narrow-screen and light/dark behavior.

Keep fixture footage out of this demonstration. Label unsupported sources
honestly; do not substitute another title, webpage player or generic clip.

## 4. Explain the cloud implementation

Use [the architecture diagram](ARCHITECTURE.md) to separate the observed source
chain from our independent Pages→Worker→D1 implementation. Show a paginated API
response supplying the visible catalogue, not an unused JSON export.

On the restricted screen, show the full snapshot denominator, current cloud row
counts, per-provider evidence, quota ledger and durable task cursor. Pause and
resume the actual import. Explain that private assets and Queues let the import
continue with the local computer off; daily free-plan windows may leave work
pending. Do not add overlapping bootstrap counts to full coverage.

## 5. Account and source boundaries

Demonstrate sign-in and profile isolation with disposable test accounts, without
filming passwords, cookies, recovery codes or private operator tokens. Explain
Firebase Spark password verification, encrypted retained credentials and private
D1 profiles. Existing private accounts require their separately supplied migration
data; missing accounts are not presented as migrated.

Show research search and one evidence relationship. Reviewing a lead does not
enable it. Metadata APIs, iframe declarations, a successful HEAD and actual
native playback are different capabilities and evidence stages.

## 6. QA, limitations and reproducibility

Show exact source-matched test and deployment results, desktop/mobile screenshots,
database integrity and a restore into a fresh verification location. Identify the
particular mapping/provider whose playback was observed, not the entire library.

Finish with the current imported/pending counts, supported provider matrix,
Cloudflare preview/production status, private GitHub commit, source archive and
backup hashes, and the executable resume command. Never film raw private state
or advertise production promotion before its release gate passes.
