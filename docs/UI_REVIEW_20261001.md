## Changes reviewed together

- Shared control geometry, spacing and quiet surfaces across the website and
  iPhone presentation. Removed decorative rules, nested search-field outlines,
  harsh square dropdowns and repeated explanatory text.
- Settings has a desktop section sidebar and a phone index leading to focused
  Playback, Appearance and Connected apps screens. Account, Security, Devices,
  Privacy & data and Profiles retain real destinations; no billing or unsupported
  preferences were added. Controls share grouped rows, switches and theme choice.
  Accent controls open only when requested. Account, sign-in,
  registration, recovery and profile management use focused forms and consistent
  disclosures. Existing approval, recovery and deletion requirements remain.
- Saved-title actions use a focused menu for play, series information, sharing
  and removal. Clearing history requires confirmation and keeps the watchlist
  and explicitly watched markers. Menu dismissal restores keyboard focus.
- The header profile menu opens without leaving the current title and offers
  profile switching, management, Settings, My List, History and ordinary sign-out.
  Failed profile saves keep the session and expose the existing recovery path.
  Switching profiles returns to the originating screen.
- Library separates My List and History. Saved titles use landscape artwork,
  recently-saved or alphabetical order, real format and viewing-history filters,
  and the actual recorded episode for resume. Saved-data decoding retains an
  available backdrop URL. Existing records without a backdrop keep the honest
  poster fallback. Legacy history/import links continue to work.
- HTML media captions and playback speed moved into a Playback settings dialog.
  Transport controls remain readable at 320px; duplicate episode arrows leave
  the phone toolbar while the dedicated episode navigation stays available.
  Opening the dialog does not remount video. Provider frames do not receive new
  controls, permissions or bridges from this change.
- Session lists expose loading, error, retry and empty states. Account actions,
  recovery values, sharing results and MyAnimeList connection/import requests are scoped to the
  active account/profile. Late results from those actions cannot overwrite a new profile; old
  imports stop issuing further requests after a switch.
- Launch readiness no longer forces a 3.3-second wait after content is ready.
  The triangle reveals with the ribbon core; soft light follows the sun's rise.
  The composition stays stable during the readiness exit. Reduced motion and
  ready-first mounts release the application correctly.
- Unknown title status and unavailable episode metadata remain unavailable;
  no episode stills, counts, ratings or provider capabilities were fabricated.

### Reproduction

Run from the repository root with the existing lockfile:

```sh
pnpm install --frozen-lockfile
pnpm check
node --test mobile-prototype/ios/source-contract.test.cjs
pnpm --dir desktop-prototype test
swift mobile-prototype/ios/validate-content-rules.swift
pnpm exec playwright install chromium webkit
node scripts/review-artwork.mjs build/public-artwork-review
SOLANIME_REVIEW_ARTWORK=build/public-artwork-review pnpm exec playwright test --workers=2 --retries=0
pnpm exec playwright test --config playwright.private.config.ts --retries=0
pnpm exec playwright test --config playwright.guard.config.ts --retries=0
node scripts/branding/test-browser.mjs --output=build/branding-review
```

If intentionally sharing an already-running fixture server on port 18787, set
`PLAYWRIGHT_REUSE_SERVER=1` for the main and Guard suites. The default still
requires a fresh test server. The private suite has its own fixture server.

The optional artwork collector reads public AniList metadata/images and writes
a hashed local manifest. Its eight identities and 16 images are separate from
Solanime's private catalogue and contain no playback sources. A requested but
empty/invalid snapshot fails; omitting the option explicitly skips those tests.
